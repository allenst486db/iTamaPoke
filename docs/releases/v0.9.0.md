# v0.9.0 — Install from a link: web app for iPhone, APK for Android

The browser build is now the main way to get the game, and it needs
nothing but a phone.

**https://allenst486db.github.io/iTamaPoke/**

## New

- **Installable offline web app (PWA).** Open the link in Safari → Share →
  *Add to Home Screen*. A service worker caches the whole app on first
  launch; after that it runs with no network, no computer, no Apple
  account, no 7-day expiry. New versions are picked up automatically on
  the next launch with internet. (`manifest.webmanifest`, `sw.js`)
- **Android APK** built by CI from the WebView shell in
  `browser_ver/native/android` and published on the same site as
  `iTamaPoke.apk`. The shell now serves the bundled files from a real
  https origin (`WebViewAssetLoader`) so the save and sprite storage
  behave, and implements the file chooser so "Load sprites…" actually
  opens the phone's picker. Debug-signed; install over it to update.
- **GitHub Pages deploy workflow** (`Build (browser)`): compiles the C++
  core with Emscripten, stamps the service worker per commit, generates
  the launcher icon from the shared mascot PNG, builds the APK, and
  refuses to publish if any sprite, cry or dex-text file is found in the
  output folder.

## Nothing is shared between players

The link only delivers the program. Each phone keeps its own save,
Pokédex, catches and loaded sprites in the app's local storage; there is
no account and no server-side state. Two people opening the same link get
two unrelated games.

## Licensing

- LICENSE §2 now explicitly permits playing the copyright holder's hosted
  build and installing it, and publishing a personal fork's copy for your
  own play; §3 still forbids re-hosting or handing out builds.
- NOTICE corrected: the species table (numbers, names, types, stats,
  evolution links) is plain data inherited from the MIT upstream and *is*
  in the code; artwork, audio and Pokédex text are not, anywhere,
  including the hosted site.

## Docs

- Install guide Path D rewritten for the link flow (iPhone / Android /
  desktop), adding the creature art on the phone itself with no computer,
  a "make your own link by forking" section, and troubleshooting. The
  earlier local-server / Xcode-shell instructions are gone.
- READMEs (EN/KO) lead with the link; install table and license section
  updated to match.

# v0.9.0 — 링크에서 설치: 아이폰은 웹앱, 안드로이드는 APK

브라우저 빌드가 이제 게임을 받는 기본 경로이고, 폰 말고는 아무것도 필요
없습니다.

**https://allenst486db.github.io/iTamaPoke/**

## 새로 추가

- **설치형 오프라인 웹앱(PWA).** 링크를 Safari로 열고 공유 → *홈 화면에
  추가*. 서비스 워커가 첫 실행 때 앱 전체를 캐시하므로 이후에는 네트워크도,
  컴퓨터도, Apple 계정도, 7일 만료도 없이 돌아갑니다. 새 버전은 인터넷이
  연결된 다음 실행 때 자동으로 반영. (`manifest.webmanifest`, `sw.js`)
- **안드로이드 APK**를 `browser_ver/native/android`의 WebView 셸로 CI가
  빌드해 같은 사이트에 `iTamaPoke.apk`로 게시. 셸은 번들 파일을 실제 https
  origin(`WebViewAssetLoader`)에서 서빙해 세이브·스프라이트 저장소가 정상
  동작하고, 파일 선택기를 구현해 "Load sprites…"가 실제로 폰의 선택 창을
  엽니다. 디버그 서명; 덮어 설치로 업데이트.
- **GitHub Pages 배포 워크플로**(`Build (browser)`): Emscripten으로 C++ 코어
  컴파일, 커밋마다 서비스 워커 버전 스탬프, 공용 마스코트 PNG에서 런처
  아이콘 생성, APK 빌드, 출력 폴더에 스프라이트·울음소리·도감 설명문 파일이
  하나라도 있으면 배포 거부.

## 플레이어 간에 공유되는 것은 없음

링크는 프로그램만 전달합니다. 세이브·도감·포획 기록·넣어둔 스프라이트는 각
폰의 앱 로컬 저장소에만 있고, 계정도 서버 상태도 없습니다. 두 사람이 같은
링크를 열면 서로 무관한 두 게임입니다.

## 라이선스

- LICENSE 2조에 저작권자의 호스팅 빌드를 플레이·설치하는 것과 개인 fork의
  사본을 본인용으로 게시하는 것을 명시적으로 허용. 3조의 재호스팅·빌드
  배포 금지는 그대로.
- NOTICE 정정: 종 표(번호·이름·타입·능력치·진화 연결)는 MIT 원본에서 물려받은
  데이터로 코드에 *들어 있고*, 그림·소리·도감 설명문은 호스팅 사이트를
  포함해 어디에도 없음.

## 문서

- 설치 가이드 경로 D를 링크 방식(아이폰/안드로이드/데스크톱)으로 다시 작성.
  컴퓨터 없이 폰에서 캐릭터 그림 넣기, "fork로 나만의 링크 만들기", 문제
  해결 포함. 이전의 로컬 서버/Xcode 셸 안내는 삭제.
- README(EN/KO) 첫머리에 링크 배치, 설치 표와 라이선스 절 갱신.
