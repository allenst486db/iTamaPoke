## 상태

원작 대비 기능적으로 완성: 펌웨어의 모든 화면과 연출이 포팅되어 있고, 동일한
게임 로직 위에서 동작합니다.

**화면:** 실시간 낮/밤 하늘이 있는 대기 화면, 스타터 선택, 알과 부화, 먹이
메뉴, 목욕, 도감 갤러리(전체/키운 것/잡은 것 필터 포함), 8페이지 스탯
카드(프로필/성격/데일리 목표/박스/배틀/메달/진행도/원정), 승리 시 캐치
제안이 붙는 야생 배틀 화면(공격/회피/휴식), 5개 타일짜리 놀이 메뉴(공/
캐치/메모/청소/타입), 훈련 자루, 이름 변경 키보드, 설정, 그리고 진화/작별/
가출 결정과 그 연출까지 전부 포함됩니다.

**성격, 데일리 목표, 박스, 도감 필터, 배틀 시스템, 캐치/메모/청소/타입
미니게임, 원정, 그리고 효과음 합성기(칩튠 파형, 4단계 소리 모드)**는
`upstream/` 서브모듈(원작 socquique/TamaPoke를 고정 참조)이 아니라 별도
커뮤니티 포크인 [ShadowEnemyx/TamaPoke](https://github.com/ShadowEnemyx/TamaPoke)
("TamaPoke — Expanded")에서 포팅했습니다 — 원작에는 이 기능들이 없습니다.
정확히 어떤 파일을 가져왔는지는
[`upstream-expanded/README.md`](upstream-expanded/README.md) 참고. 박스
화면은 야생 배틀에서 이기고 잡은 개체만큼 채워집니다.

**도감이 151종이 아니라 386종(1~3세대)입니다.** 늘어난 건 목록뿐입니다:
1세대 항목은 기존과 바이트 단위로 동일하고, 희귀도·진화·스탯·배틀 규칙은
아무것도 바뀌지 않았습니다. 추가된 항목은 세 번째 포크인
[DylanPDao/TamaPoke](https://github.com/DylanPDao/TamaPoke)에서 옮겨온
것이며, 무엇을 가져오고 무엇을 가져오지 않았는지는
[`upstream-expanded/README.md`](upstream-expanded/README.md)에 정리해뒀습니다.
기존 세이브는 등록해둔 종을 그대로 유지합니다.

**사운드**는 녹음이 아니라 소프트웨어로 재합성한 것으로, 포크 자체의
audio.cpp가 만들어내는 것과 동일한 칩튠 파형(사각파/삼각파/소프트파/노이즈,
슬라이드와 효과별 볼륨 포함)입니다 — 자세한 방법은 [포팅 방식](#포팅-방식)
참고.

**의도적으로 다르게 만든 부분 하나:** 설정 화면에 수동 시계가 없습니다.
원본 하드웨어는 시간을 알 방법이 따로 없어서 손으로 시계를 맞추지만,
폰은 이미 시간을 알고 있어서 그냥 그걸 그대로 씁니다.

## 게임 방법 (실제 수치)

원작과 같은 엔진이라 수치도 동일합니다 — 이 표는
[원작 README](https://github.com/socquique/TamaPoke#game-manual-the-actual-numbers)의
표를 그대로 옮겨온 것입니다. 쉬운 설명 버전은 [게임 방법](docs/GAMEPLAY.ko.md)
참고.

**레벨업:** 실제 1분 = 게임 내 1분. 실제 **1시간마다 레벨 +1** — 잘 돌본다고
빨라지지 않고, 방치하면 진화가 *지연*됩니다. 앱을 닫아둬도 시간은 계속
흐르고(원본의 RTC처럼), 다시 열면 최대 **2주**까지 따라잡습니다.

**4개 스탯(0~100):** FOOD, JOY, ENE(기력), HYG(청결). 시작값 80/80/80/100,
깨어있는 동안 분당 FOOD −2, ENE −1(과체중이면 −1 추가), HYG −1(보이는
응가당 −4 추가), JOY −1(FOOD나 HYG가 30 미만이면 각각 −2 추가). 스탯이
10 이하가 되면 **관리 실패** — 진화가 1레벨 지연되고 유대감이 식습니다.

**행동:** 열매는 +25 FOOD(숨겨진 최애 맛이면 더 많이 + 유대감 상승); 사탕은
+10 FOOD/+12 JOY지만 체중 증가; 공 미니게임은 SPEED 훈련; 훈련 자루는
STRENGTH 훈련; 목욕은 응가 제거; 쓰다듬기는 JOY/유대감 소폭 상승; 수면은
모든 감소를 약 4배 늦추고 관리 실패·가출을 막아줌.

**알:** 첫 캐릭터는 13종(피츄, 피카츄, 플러시, 마이농, 1-3세대 스타터 9종)
중에서 고르며, 한 페이지에 5종씩 3페이지로 넘겨서 선택합니다. 이후 알은 매번 희귀도를
굴리며(전설은 25종 이상 등록해야 등장 시작), 아직 완성 못한 진화 라인
쪽으로 편향되고, 스트릭·유대감이 좋으면 향상되며, 이로치 확률은 기본
**1/48**에서 **1/8**까지 올라갑니다.

**진화:** 레벨이 해당 종의 기준 이상이고 *동시에* 그 순간 모든 스탯이 40
이상이어야 합니다. 절대 자동으로 일어나지 않고, 항상 버튼을 눌러야 합니다.
1세대 6종(골뱃, 롱스톤, 럭키, 시드라, 스라크, 폴리곤)은 세대를 넘어
진화하며, 진화형이 4세대 이후에만 있는 종은 여기서 최종 진화형입니다.

**엔딩:** 작별(최종 진화형, 3일 경과, 직접 선택 — 다음 알에 축복), 가출(4개
스탯 전부 0으로 한 시간 — 다음 알에 저주), 놓아주기(아무 때나 길게 누르기).
셋 다 새 알로 이어집니다.

## 포팅 방식

펌웨어는 고정된 **466×466** 프레임버퍼에 그림을 그립니다. 이 좌표 공간을
그대로 유지한 채 아이폰/워치 화면 크기에 맞는 스케일 변환 하나만
적용했습니다 — 그래서 `drawScene`, `drawBars` 같은 그리기 함수들이 원본
C++에서 **한 줄 한 줄 그대로** 포팅됩니다.

게임 로직 자체는 **다시 작성하지 않았습니다.** 원본 `pet.cpp`와 `i18n.cpp`가
그대로 컴파일되며, Arduino/ESP32 전용 부분(타이머, 난수, 키/값 저장소)만
작은 셰임 헤더로 대체합니다. 얇은 브리지 레이어가 그 C++ 객체를 Swift UI에
노출할 뿐, 시뮬레이션·스탯 감소·진화 규칙·알 확률 중 어느 것도 재구현하지
않았습니다.

사운드도 마찬가지입니다: 펌웨어는 자체 오디오 칩에서 칩튠 파형(사각파,
삼각파, 더 부드러운 파형, 노이즈, 슬라이드와 효과별 볼륨까지 — Expanded
포크 자체의 audio.cpp)을 생성합니다. 여기엔 그런 칩이 없어서, 새로운 소리를
쓰는 대신 동일한 파형(같은 음표 테이블, 같은 샘플레이트, 같은 엔벨로프)을
소프트웨어로 합성합니다.

## 설치

어느 경로로 설치하든 **캐릭터 아트 없이** 설치됩니다 — [스프라이트](#스프라이트)

## 스프라이트

앱은 포켓몬 아트를 내장한 채로 배포되지 않습니다 — 별도 라이선스가 있는
팬아트이기 때문입니다([라이선스](#라이선스) 참고). 그래서 어떤 빌드에도
포함되지 않고, 설치 후에 따로 추가합니다.

**간단한 방법 — 어떤 설치 방법으로 깔았든 동일하게 동작:** **파일** 앱 →
**내 iPhone → iTamaPoke** → `mons`라는 새 폴더 만들기 → `.bin` 스프라이트
파일 복사해 넣기([upstream 저장소](https://github.com/socquique/TamaPoke)의
`tools/sdcard/mons`에서 받으면 됨 — 정확한 클릭 위치는 [설치
가이드](docs/INSTALL.ko.md) 참고). 넣은 뒤 앱을 재시작하세요. `thumbs.bin`도
꼭 같이 넣어야 도감 화면이 텅 비지 않습니다. 애플워치도 페어링되어 있고
워치 앱도 설치했다면, 아이폰 앱을 잠깐 열어두면 자동으로 같은 파일을
워치로 보내려고 시도합니다 — 그 다음 워치 앱을 열면 바로 도착하는 경우가
많습니다.

**Xcode로 직접 빌드하는 경우:** `Scripts/fetch_sprites.sh`가 `upstream/`
서브모듈에서 스프라이트를 바로 빌드에 복사해 넣어서, 빌드하는 순간 앱
안에 내장됩니다. 정확한 명령어는 [docs/INSTALL.ko.md](docs/INSTALL.ko.md)의
"경로 C" 참고.

파일이 없는 종은 화면이 깨지지 않고 그냥 플레이스홀더로 표시되므로,
일부만 넣어도 괜찮습니다.

## 도감 설명문

도감에서 포켓몬을 누르면 2페이지짜리 상세 화면이 열립니다 — 첫 페이지는
초상화와 타입 칩, 둘째 페이지는 도감 설명문입니다. 이 설명문은 Nintendo /
Game Freak의 저작물이라, 위의 스프라이트와 똑같이 **저장소에 포함하지
않습니다**. 화면은 `mons/dex_entries.txt`를 읽으며, 경로 규칙도 스프라이트와
같습니다: `Documents/mons/`(파일 앱 → 내 iPhone 안에 → iTamaPoke)를 먼저
보고, 없으면 앱 번들을 봅니다.

`Scripts/fetch_dex_entries.sh`가 [PokéAPI](https://pokeapi.co)에서 그 파일을
만들어줍니다 — 원작이 `dex.h`의 전투 스탯을 가져오는 것과 같은 출처입니다:

```bash
Scripts/fetch_dex_entries.sh              # 전체 종, 영어
Scripts/fetch_dex_entries.sh --lang es    # 스페인어
Scripts/fetch_dex_entries.sh 1 4 7        # 이 셋만
```

형식은 한 줄에 하나씩 `<도감번호>|<설명문>`이고, 빈 줄과 `#`으로 시작하는
줄은 무시되므로 직접 작성해도 됩니다:

```
122|손으로 보이지 않는 벽을 만들어낸다.
```

파일 하나에 한 가지 언어만 담깁니다 — 언어를 바꾸려면 `--lang`을 바꿔 다시
실행하세요. 파일이 없으면 해당 페이지에 `NO DEX ENTRY`라고만 표시되고,
나머지 화면은 그대로 동작합니다.

## 저장과 파일 앱

아이폰 앱은 **파일 → 내 iPhone → iTamaPoke**에 `iTamaPoke-save.json`으로
저장 데이터를 두고, 저장할 때마다 자동으로 다시 씁니다. 백업하려면 이
파일을 복사해두거나 다른 기기로 옮기세요.

복원하려면 `iTamaPoke-import.json`이라는 이름으로 같은 위치에 넣고 앱을
여세요 — 한 번 로드된 뒤 이름이 바뀌어서 재시작해도 다시 불러와지지
않습니다. **이건 그 기기의 현재 캐릭터를 대체합니다.**

애플워치 앱은 완전히 별도의 저장 데이터를 가지며 파일 폴더가 없습니다.

## Upstream

`37ba1c4`에 고정되어 있습니다. upstream 수정사항을 받아오려면:

```bash
git submodule update --remote upstream
```

그런 다음 다시 빌드하세요 — 셰임 레이어가 유일한 연결 지점이라 대부분의
upstream 변경은 이쪽에 비용이 들지 않습니다.
